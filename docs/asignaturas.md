# Overwatch por asignatura

El proyecto está pensado para poder presentarlo y defenderlo en distintas asignaturas.
Cada pieza debe poder explicarse por separado, sin depender de las demás.

| Asignatura | Pieza que se defiende | Qué se puede demostrar |
| --- | --- | --- |
| Programación de servicios y procesos | Servicio Python (`service/`) | Hilos, procesos, `subprocess`, comunicación por red |
| Acceso a datos | Histórico de métricas | Guardar y consultar las lecturas (por ejemplo, SQLite) |
| Desarrollo de interfaces | Dashboard de escritorio (`desktop/`) | Interfaz reactiva con gráficas en tiempo real |
| Programación de dispositivos móviles | Cliente Android | Una app que consume el mismo servicio |

Las piezas que aún no existen figuran como previstas en la [hoja de ruta](roadmap.md).

## Cómo preparar una defensa

1. Elegir la pieza y abrir su fase en la [hoja de ruta](roadmap.md).
2. Repasar las entradas del [diario de progreso](progress/README.md) que la construyeron.
3. Leer en [decisiones](decisiones.md) el porqué de cada elección: es lo que más se pregunta.
4. Ensayar la demostración en limpio, partiendo de un clon nuevo del repositorio.
